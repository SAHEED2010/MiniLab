# Engineering journal

**Status: Template for future work sessions**

Use this journal to record what actually happened during each MiniLab session. Distinguish observations from assumptions, and record failures as useful engineering evidence. Do not backfill measurements, test results, or hardware progress that was not observed.

Copy the template below for each session and replace the placeholders.

## Session N — YYYY-MM-DD

### Goal

What was this session intended to accomplish?

### Work completed

What actions were actually completed? Include relevant files, diagrams, code, or component research.

### What I learned

What new hardware, electronics, firmware, or debugging knowledge did the session produce?

### Problems encountered

What failed, remained unclear, or needs further investigation?

### Debugging

What hypotheses, experiments, observations, or changes were used to investigate problems?

### Decisions

What decisions were made, what alternatives were considered, and what evidence supported them?

### Time spent

Record an honest estimate of the time spent.

### Photos/screenshots

Add links or filenames for useful evidence. If no physical hardware exists yet, say so rather than adding a placeholder image.

### Next steps

What is the smallest clear next action for the following session?

## Why keep a journal?

An engineering journal preserves the reasoning behind design choices, makes debugging repeatable, exposes assumptions, and provides an honest record of progress. For a first hardware project, it also turns mistakes and unresolved questions into part of the learning process instead of losing them between sessions.
